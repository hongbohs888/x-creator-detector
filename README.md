# X 博主探测

刷到一个号，马上知道它的底细。

一个 Chrome 插件，在 X（x.com）页面上直接显示每个账号的粉丝数、账号标签（大V、互粉号、老号重启……），以及「他最常转谁的帖」。

数据全部来自 X 页面自己发出的请求的响应。插件不发任何额外请求，不需要登录授权，不需要 API Key，数据只存在本机浏览器里。

## 安装

**方式一：下载压缩包（推荐）**

1. 到 [Releases 页面](https://github.com/hongbohs888/x-creator-detector/releases/latest) 下载最新的 `x-creator-detector-v*.zip`，解压
2. Chrome 地址栏打开 `chrome://extensions`
3. 打开右上角「开发者模式」
4. 点「加载已解压的扩展程序」，选择刚才解压出来的文件夹（里面能直接看到 `manifest.json` 的那一层）
5. 打开或刷新 x.com 页面

**方式二：克隆仓库**

```bash
git clone https://github.com/hongbohs888/x-creator-detector.git
```

然后按上面第 2～5 步操作，加载仓库里的 `extension` 文件夹。

需要 Chrome 111 或更高版本。解压出来的文件夹不要删，Chrome 是直接从那里读取插件的。更新版本时，替换文件夹里的内容，再到 `chrome://extensions` 点插件卡片上的刷新按钮，并刷新 X 页面。

## 功能

### 粉丝数徽标

时间线、评论区、引用卡片、关注/粉丝列表、个人主页，用户名旁边都会显示粉丝数。颜色按量级分五档：

| 粉丝数 | 颜色 |
|---|---|
| 1000 以下 | 灰 |
| 1000 ～ 1 万 | 蓝 |
| 1 万 ～ 10 万 | 绿 |
| 10 万 ～ 100 万 | 橙 |
| 100 万以上 | 红 |

### 标签

| 标签 | 默认判定 |
|---|---|
| 互关 | 你们互相关注 |
| 关注了你 | 他关注了你，你还没回关 |
| 大V | 粉丝至少 1 万，并且粉丝数是关注数的 10 倍以上 |
| 疑似互粉 | 关注了超过 400 人，并且粉丝数不到关注数的 10 倍 |
| 互粉号 | 比疑似互粉更严重的一档：关注了超过 400 人，并且关注数和粉丝数接近（关注是粉丝的 70%～150%）。红底显示，标了它就不再标疑似互粉 |
| 老号重启 | 注册超过 2 年，并且满足任意一种：① 停更至少 6 个月，最近 6 个月内恢复，恢复后已发至少 10 条；② 最近 30 天至少发了 15 条，并且发帖速度是以前的 5 倍以上 |
| 新号 | 注册不到 180 天（半年） |
| 老号 | 注册超过 3 年 |
| 高互动 | 每 100 次浏览，至少 3 次互动 |
| 低互动 | 每 1000 次浏览，不到 1 次互动，并且粉丝至少 1000 |

几点说明：

- **疑似互粉和互粉号的思路**：正常人关注不了那么多人，很多大V 只关注一两百个。5000 粉的账号关注 400 人以内算正常；关注数很高、粉丝却没多出多少，多半是靠关注换来的。关注和粉丝几乎一样多的，直接标更严重的「互粉号」。两种情况两档都不标：关注数不到 400 的小号；关注比粉丝多出一大截的号（比如 50 粉、关注 600），那是关注了很多人但没人回关的普通账号，不是互粉。
- **老号重启怎么算**：有两种判定方式，满足一种就标。
  - 方式 ①（最准）：他主页的帖子是按时间连续排的，相邻两条之间隔了半年以上，就是实打实的停更。停更之后最近半年内又恢复、并且已经发了 10 条以上，就是重启。详情卡会写出证据，比如「停更 27 个月后在 2026-05 恢复发帖，之后已发 25 条以上」。这种方式要打开他的主页、往下翻到停更前的帖子才看得出来；没翻到之前只会标「老号」。
  - 方式 ②：翻不到停更前的帖子时（比如重启后已经发了几百条），看最近 30 天的发帖速度是不是比以前的平均速度快 5 倍以上。
  - 标了「老号重启」就不再重复标「老号」。
- **互动怎么算**：互动 = 点赞 + 转发 + 回复 + 引用，只算他自己发的帖子。每条帖子单独算互动率，再取中位数，所以一条爆款或一条投了广告的帖子带不偏结果。发出不到 6 小时的帖子不算，至少看到 3 条、总浏览量过 1000 才判断。
- 判定逻辑都在 `extension/rules.js`，数字门槛的默认值在 `extension/defaults.js`。

### 悬停详情卡

鼠标移到徽标上，显示精确粉丝数、关注数、粉丝/关注比、注册时间、帖子数、近几天粉丝涨跌、互动率、常转的人，以及每个标签的判定依据。

粉丝涨跌靠插件每天记一次快照来算，所以装上后要过几天才有数字。

### 转发榜

打开任意账号的主页，资料区下方会出现「转发榜」，按被转发次数列出他最常转的人。纯转发记「转」，引用转发记「引」。

X 现在把转发单独放在主页的 Reposts 标签里。点面板上的「多翻几屏」，插件会切到 Reposts 标签并自动往下翻（默认 8 屏），翻完回到顶部。再点一次按钮可以中途停止。

榜单只统计页面已经加载出来的帖子，面板上会写明样本量。同一个账号多次访问会累加，按帖子去重。

榜单上还能做两件事：

- **看他具体转了哪几条**：点每行右侧的「转 9 · 引 2 ▾」展开明细，最新的在前。每条显示帖子开头和他转发的时间，点击跳到帖子。纯转发跳原帖，引用跳他带评语的那一条。
- **找他常转、但你还没关注的人**：每行的 @账号 后面标着「你还没关注」或「已关注」。点面板右上的「只看未关注」，榜单只留你还没关注的人。

### 运行状态

点工具栏上的插件图标，弹窗顶部有一行运行状态，用来分清「插件失效了」和「只是页面没加载」：

| 圆点 | 含义 |
|---|---|
| 绿 | 运行正常，显示最近 5 分钟读到多少个账号 |
| 黄 | 本页还没拦到 X 的请求，或者刚拦到几个还没有账号数据。刷新或滚动一下 |
| 红 | 拦到了不少响应，却一个账号都没解析出来。多半是 X 改了数据结构，插件需要更新 |
| 灰 | 当前标签页不是 X，或者页面是在装/更新插件之前打开的，刷新即可 |

### 本地数据自动清理

数据存在浏览器的本地存储里，占的是磁盘。插件会自己控制大小：

- **按天数过期**：默认 30 天没再出现的账号、30 天没再打开主页也没有新转发的转发记录，会被自动删掉。弹窗里可以改成 7 天、90 天或不自动清理，改完立刻按新天数清一次。
- **定时执行**：后台每 6 小时清理一次，浏览器启动时也清一次，X 页面没开着照常执行。
- **数量上限**：最多保留 3000 个账号、200 份转发记录，超了先删最久没出现的。
- **页面内存也有上限**：X 标签页一直开着不关，内存里的数据同样按上面的规则裁剪。

弹窗底部会显示当前记录了多少数据、实际占用多少磁盘，以及上次清理的时间和结果。

## 设置

点浏览器工具栏上的插件图标，可以调整：

- 总开关
- 标签显示方式：全部显示、只留最重要的一个、只显示粉丝数
- 标签规则：每个标签一张卡片，带开关、一句话解释和可改的数字
- 是否显示悬停卡、转发榜，榜单显示前几名，一次翻几屏
- 自动清理的保留天数
- 恢复默认、清空本地数据

默认值在 `extension/defaults.js` 里，每一项都有注释。

## 已知限制

- 插件只能看到 X 已经加载的数据。一个账号从没在你的页面上出现过，就没有徽标。
- 转发榜的样本取决于翻了多少屏，不代表他的全部转发历史。
- 「多翻几屏」走的是 X 自己的滚动加载，短时间内连点很多次，X 可能暂时提示加载失败，等几分钟即可。
- 互动率的样本是你恰好看到的那几条帖子，只能当参考。
- X 改版页面结构或接口字段后，插件可能需要跟着调整。

## 目录

```
extension/        插件本体（加载这个文件夹）
  manifest.json
  inject.js       页面主环境：旁路读取 X 请求的响应
  content.js      画徽标、详情卡、转发榜，管理本地数据
  rules.js        标签规则：每个标签怎么判定
  background.js   后台定时清理过期数据
  content.css     样式
  defaults.js     默认设置
  popup.html/js   设置弹窗
  icons/
test/
  inject.test.js  解析逻辑测试：node test/inject.test.js
  rules.test.js   标签规则测试：node test/rules.test.js
  cleanup.test.js 自动清理测试：node test/cleanup.test.js
  make_icons.py   重新生成图标：python3 test/make_icons.py extension/icons
```

## 隐私

- 插件只读取 X 页面自己发出的请求的响应，不发起任何额外的网络请求，不调用 X 的 API。
- 不需要登录授权，不需要 API Key。
- 所有数据只保存在你自己浏览器的本地存储里，不上传到任何地方。
- 申请的权限只有两个：`storage`（保存设置和本地数据）和 `alarms`（定时清理过期数据）。
